2. PRESENT FEATURES ALREADY BUILT & HOW THEY WORK
--------------------------------------------------------------------------------

[FEATURE 1: Configurable Attribution & Ingestion Engine]
- Files: core/attribution.py, core/importer.py, config/attribution.yaml
- Tools/Libraries: Pydantic v2, PyYAML, Pandas
- Part It Plays: Ingestion entry point for raw logs and HTTP proxy requests.
- Problems Solved: Unattributed shadow AI spend, disparate tag naming across teams
  (e.g., "Engineering" vs "eng" vs "ENGINEERING"), and dirty or corrupted records.
- How It Works: Extracts HTTP headers (X-Team, X-Feature, X-User, X-Env) or CSV
  columns, normalizes casing/whitespace, applies regex alias mappings, and
  explicitly tags missing attribution as 'unattributed' rather than dropping rows.
- Efficiency Gain: Replaces manual spreadsheet cleaning with instant sub-millisecond
  in-memory pipeline parsing.

[FEATURE 2: Deterministic Decimal Cost Engine & Invariant Verifier]
- Files: core/cost_engine.py, core/models.py
- Tools/Libraries: Python Decimal (ROUND_HALF_UP), DuckDB, Pandas
- Part It Plays: Financial core calculating deterministic spend per request.
- Problems Solved: Floating-point precision drift ($0.00000000000004 errors), silent
  zero charges for unpriced or newly launched models, and mathematical discrepancy.
- How It Works: Calculates C_input = (T_in * P_in)/1e6, C_output = (T_out * P_out)/1e6,
  C_cached = (T_cached * P_cached)/1e6. Enforces non-negotiable invariant:
  Sum(Team Spend) == Sum(Model Spend) == Sum(Date Spend) == Grand Total.
  Flags missing models with missing_price=True without zeroing costs.
- Efficiency Gain: Uses DuckDB analytical views to process thousands of requests
  in under 50ms without database overhead.

[FEATURE 3: Dual Provider Format Proxy Adapter & Persistent Usage Store]
- Files: scripts/mock_proxy.py, core/usage_store.py
- Tools/Libraries: FastAPI, httpx, DuckDB embedded SQL
- Part It Plays: Live multi-provider reverse proxy and zero-prompt token store.
- Problems Solved: Lack of live ingestion; inability to handle multiple provider schemas.
- How It Works:
  - OpenAI Format: /v1/chat/completions (choices, usage.prompt_tokens, etc.)
  - Google Gemini Format: /v1beta/models/{model}:generateContent (usageMetadata)
  - Records request IDs, models, tokens, and deterministic costs in a persistent
    DuckDB ledger without storing private prompts or API keys.
- Efficiency Gain: Zero-code integration by pointing SDK base URLs to the proxy;
  direct DuckDB SQL aggregations avoid loading full dataframes into memory.

[FEATURE 4: Streamlined Executive Dashboard (Trend View Optimized)]
- Files: app.py, .streamlit/config.toml
- Tools/Libraries: Streamlit, Plotly Express/Graph Objects, Custom SaaS CSS Theme
- Part It Plays: Interactive visual cockpit for engineering and finance teams.

- Recent Refinement:

    evolution, and feature workload breakdown.
  - Formal reconciliation and invariant verification remain fully accessible via
    scripts/run_independent_validation.py, reports/reconciliation_report.md, and
    the /api/v1/reconciliation REST endpoint.

[FEATURE 5: Demonstration Security & Access Control (P0 Scope)]
- Files: api/main.py, .streamlit/config.toml
- Tools/Libraries: FastAPI, Starlette, secrets, TrustedHostMiddleware, CORSMiddleware
- Part It Plays: Defends API and UI from unauthorized access, timing attacks, and DoS.
- Problems Solved: Exposure of sensitive request prompts/user IDs, rogue remote calls,
  oversized body memory exhaustion, timing attacks on credentials.
- How It Works: Binds Streamlit and Uvicorn strictly to 127.0.0.1; rejects remote
  callers with HTTP 403 when FINOPS_API_TOKEN is unset; validates Bearer tokens
  using constant-time secrets.compare_digest; caps request bodies at 64 KiB;
  requires explicit operator confirmation checkboxes before exporting logs/audits.
- Efficiency Gain: Secure by default; protects server resources from malicious floods.

[FEATURE 6: Statistical Anomaly Detection Engine (FR-09)]
- Files: core/anomaly_engine.py, tests/test_guardrails_anomaly.py
- Tools/Libraries: NumPy, Pandas, Scipy statistical methods
- Part It Plays: Early warning system flagging cost spikes, runaway loops, and prompt bloat.
- Problems Solved: Unexpected "bill shock" caused by runaway recursive agent loops or
  accidental context window blowups (oversized system prompt injections).
- How It Works:
  1. Cost Spikes: Evaluates Z-scores per request; flags items > 3.0 sigma as anomalies.
  2. Prompt Bloat: Evaluates Upper IQR Fences (Q75 + 3.0*IQR); detects abnormal prompt bloat.
  3. Runaway Users: Detects user concentration where a single user drives >20% of spend.
- Efficiency Gain: Proactive notification prevents runaway costs before monthly billing.

[FEATURE 7: FinOps Budget Guardrails & Policy Enforcement (FR-10)]
- Files: core/guardrails.py, api/main.py (/api/v1/guardrails, /api/v1/guardrails/check)
- Tools/Libraries: Pydantic v2, Decimal, FastAPI
- Part It Plays: Pre-flight and post-flight spend policy governance per team.
- Problems Solved: One department consuming 90% of the company's shared AI budget.
- How It Works: Tracks team-level monthly quotas, warning thresholds (80%), and
  critical limits (100%). Provides /api/v1/guardrails/check to evaluate potential
  requests and return ALLOW, WARN, or BLOCK before calling expensive LLM APIs.
- Efficiency Gain: Shifts FinOps from reactive end-of-month reporting to real-time
  proactive cost prevention.

[FEATURE 8: Headless Chrome DOM Verification Test Suite]
- Files: tests/dom_test.py
- Tools/Libraries: Chrome DevTools Protocol (CDP), websockets, Python asyncio
- Part It Plays: End-to-end browser and DOM testing for Streamlit applications.
- Problems Solved: UI regression bugs, unrendered React DOM components, broken tabs.
- How It Works: Launches Chrome in headless mode on port 9222, connects via WebSocket,
  and verifies title, H1 headers, KPI values, buttons, and tab clicks dynamically.
